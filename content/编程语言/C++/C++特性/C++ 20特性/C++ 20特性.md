# module - 模块
在c++中每个cpp都单独编译，最后将他们链接在一起，由于每个编译单元都是独立编译的，导致各个编译单元无法沟通，采用头文件建立各个编译单元的桥梁，头文件中描述接口的信息。

现有的是include机制，即将头文件包含进cpp或者h文件，如果包含两次，那么会遇到重复定义的问题，inlude会递归调用，因此需要主要包含顺序，不要相互包含（通过前置声明解决），也可以使用诸如#ifndef、#define 和 # endif之类的指令解决。

c++编译慢的一个原因就是include机制会导致的，一个公共的头文件很可能被N个编译单元包含，这N个编译单元都会去编译头文件，尤其是修改这个公共头文件，那么就会导致所有相关的编译单元重编。

在加入模版机制之后，include更会导致大量的文件复制（现有的模版机制需要将模版的实现加入到h文件，编译会复制量变大）。

module机制的推出即为了解决上述问题（其他语言比如java、python早已支持）。

语法结构：
```c++
//helloworld.ixx
export module helloworld;   //导出helloworld模块
import std.core;    //导入stl相关模块

export  void hello()  {
    std::count << "hello world" << std::endl; //导出hello函数
}

//module_test.cpp
import helloword;

int main() {
	hello();
	return 0;
}

```

helloworld.ixx是接口文件，编译器编译helloworld.ixx会生成一个helloworld.ifc，该文件包含了模块的元数据，module_test.cpp会生成module_test.obj。



# concept - 概念

## 引子 - SFINAE

SFINAE（Substitution Failure Is Not An Error，替换失败不是错误）主要是指在函数模板重载时，当模板形参替换为指定的实参或由函数实参推导出模板形参的过程中出现了失败，则放弃这个重载而不是抛出一个编译失败。

在 SFINAE 规则中，模板形参的替换有两个时机，首先是在模板推导的最开始阶段，当明确地指定替换模板形参的实参时进行替换；其次在模板推导的最后，模板形参会根据实参进行推导或使用默认的模板实参。
