# 核心组件架构
它最初的设计灵感来源于 Facebook 的 [[Haystack 架构]]，特别擅长处理海量小文件的存储与访问。
SeaweedFS 的架构设计非常清晰，主要包含以下三个核心角色：

| 组件名称          | 主要职责 | 特点                                                       |
| :------------ | :--- | :------------------------------------------------------- |
| Master Server | 集群大脑 | 管理 Volume Server 的注册，分配 Volume ID，维护 Volume ID 到服务器的映射表。 |
| Volume Server | 数据存储 | 存储实际的文件数据。它管理自己的元数据（在内存中），负责文件的读写操作。                     |
| Filer         | 功能扩展 | 基于 Master 和 Volume 构建。提供目录结构、S3 兼容接口、WebDAV、身份验证等功能。     |
# 适用场景
- 海量小文件存储： 如用户头像、聊天图片、日志文件等。
- 云原生环境： 支持 Kubernetes CSI Driver，适合作为容器平台的持久化存储。
- 数据湖/数据备份： 利用其低成本的纠删码模式和冷数据归档功能。

总体而言，SeaweedFS 是一个轻量级但功能强大的存储系统，相比 MinIO 等对象存储，它在小文件处理上更具优势；相比 HDFS，它又更加灵活且资源占用更少。
