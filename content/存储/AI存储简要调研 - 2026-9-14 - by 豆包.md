AI 存储不是传统分布式存储简单扩容，核心矛盾是**内存墙 / 数据搬运瓶颈**，分为**训练存储、推理存储（KV Cache）、向量 / RAG 存储、数据湖**四大主线；架构以**分层存算分离**为主，新方向是 AI 原生存储、存算一体、DPU 卸载、KV 专用存储。  
 
# 1 AI 存储四大业务方向（场景 + 需求特征）  
1. 大模型训练存储（预训练 / 微调）
**负载特征**：**大块顺序读为主，伴随周期性 Checkpoint 写**；万卡集群下要求极高聚合带宽，最怕 IO 阻塞导致 GPU 空转。  
- 数据侧：海量训练数据集（图片、视频、文本），大量小文件痛点；需要预取、shuffle、样本混洗
- 模型侧：权重、梯度、优化器状态、Checkpoint 快照，高频持久化与快速恢复
- 核心指标：**聚合带宽、顺序吞吐、元数据扩展能力、EC 纠删码**
- 典型产品：Ceph、Lustre、BeeGFS、ParaStor，云厂商 AI 数据湖

2. 大模型推理存储（重点：KV Cache 存储，当前最热赛道）
**负载特征**：随机小 IO、读写混合、长上下文下 KV 缓存爆炸性增长；HBM 容量昂贵且有限，必须分层卸载。  
行业通用 G1~G4 分层模型：

- G1：GPU HBM，热 KV、正在解码的上下文（最低延迟、最贵）
- G2：Host DRAM，次热 KV 缓存
- G3：节点本地 NVMe SSD，温 KV；新出现 G3.5 层（独立分布式 KV 存储池，如月之暗面 Mooncake、阿里云 KVCacheStore）
- G4：远端共享对象 / 文件存储，模型权重、冷历史上下文、归档数据
核心目标：**KV Cache 池化，打破单卡显存上限，实现无限长上下文**；把部分 KV 下沉到 SSD/NVMe-oF，降低 HBM 占用，提升并发 QPS，平衡延迟与 TCO。  

3. RAG 向量存储（向量数据库）
**负载特征**：高并发向量相似度检索、元数据管理、向量索引构建 / 更新；混合向量、文档、图片多模态数据。

- 存储对象：embedding 向量、原始文档、chunk 文本、索引（HNSW 等）
- 需求：低延迟向量检索、索引持久化、多租户、元数据与向量分离存储
- 产品：Milvus、Qdrant、Chroma、PGVector；底层可跑在对象 / 全闪分布式存储之上

4. AI 数据湖（全生命周期数据管理）
覆盖原始数据、清洗、标注、版本、数据集、模型版本、评估结果；**非结构化数据为主**，兼顾归档、权限、数据血缘、数据脱敏。

- 格式：Parquet、Arrow、TFRecord、WebDataset、tar 打包（解决海量小文件）
- 能力：S3 兼容、分层冷热迁移、数据版本、数据流水线对接 Dataloader

> 补充边缘 AI 存储：端侧 / 车载，低功耗、高可靠性，UFS/PCIe/NVMe，面向感知数据 + 端侧小模型推理。  

# 2 主流架构分类  
1. 传统高性能并行文件系统架构（训练主流）
Lustre、BeeGFS，集中元数据 + 分布式数据 OSD，面向大带宽顺序 IO。 优点：万卡训练成熟；缺点：元数据单点瓶颈，小文件性能差，成本高，不擅长推理 KV 随机负载。  

2. 存算分离分布式存储（训推一体主流）
**计算集群与存储集群物理解耦**，通过高速网络 RDMA/NVMe-oF 访问共享存储池。

- 存储池：对象 + 文件 + 块多协议（S3/POSIX/NFS）
- 网络：RoCE、InfiniBand，DPU 卸载协议（BlueField）
- 典型：Ceph、RustFS、NVIDIA STX 参考架构 优点：容量弹性扩容，资源池化，训推共享一套数据湖；缺点：网络是瓶颈，长距离访问延迟更高。

3. 多级分层缓存架构（推理 KV Cache 专用架构，新范式）
HBM→DRAM→本地 NVMe→分布式 KV 存储池→对象冷存储，**冷热数据自动迁移**，不是固定层级，由调度引擎管理。 代表：Mooncake（月之暗面）、KVCacheStore；KV 存储独立池化，与 GPU 算力解耦，全局 KV 共享，支持公共前缀复用，大幅提升缓存命中率。  

4. 存算一体 / 近存计算（下一代架构，尚在产业化）

# 3 核心关键技术  
### 3.1.1 介质层

1. HBM：GPU 高带宽内存，G1 层，带宽极高、容量小、单价贵
2. DRAM：主机内存，G2
3. NVMe SSD / AI SSD：PCIe4.0/5.0；NVMe-oF（网络裸盘协议，RDMA 承载），G3/G3.5 主力
4. HBF 高带宽闪存：3D 堆叠 NAND，接近 HBM 带宽，下一代候选
5. HDD / 大容量 SSD：冷归档层

### 3.1.2 网络与协议

- NVMe-oF + RDMA/RoCE：GPU 直连远端存储，零拷贝，绕过主机 CPU，GDS（GPU Direct Storage），GPU 直接读写存储，不经过主机内存，大幅降低 CPU 开销
- DPU 卸载：BlueField 等网卡，把 NVMe-oF、加密、压缩、纠删码、元数据操作卸载到 DPU，释放 CPU/GPU 算力（NVIDIA STX 核心思路）

### 3.1.3 存储软件核心技术

1. **小文件优化**：后台合并成大分片（WebDataset、TFRecord、Parquet），批量预读、预取 shuffle 数据，元数据分布式化，解决百万级小文件随机读灾难
2. **Checkpoint 优化**：异步快照、增量 Checkpoint、压缩、分布式并行写，减少训练中断保存时阻塞 GPU
3. **KV Cache 管理**：冷热分级调度、自适应淘汰（超越 LRU）、KV 压缩、前缀复用、KV 全局池化；长上下文场景支持 KV 按需卸载 / 召回，部分方案支持重算兜底策略（DeepSeek CSA/SWA）
4. 纠删码 EC：替代多副本，节省空间；AI 存储常用 4+2、8+3；高速层采用副本保证低延迟
5. 数据版本、数据血缘、多租户、数据脱敏、权限管控（数据湖必备）
6. 向量索引持久化：HNSW、IVF 等索引在 SSD 上的增量更新、内存 - 磁盘索引分层

### 3.1.4 硬件卸载技术

- DPU：协议卸载、压缩 / 解压、校验、EC 编码、加密
- 计算型 SSD（AI SSD）：盘上做向量距离、数据过滤、解压，数据原地处理，减少 IO 传输量

## 3.2 核心挑战总结

1. **训练**：海量小文件、元数据瓶颈、万卡集群下带宽不够、Checkpoint IO 冲击
2. **推理**：KV Cache 容量爆炸、随机小 IO 高延迟、HBM 成本过高、跨节点 KV 共享
3. **通用**：数据搬运（内存墙）、网络拥塞、TCO 高、冷热数据分层调度复杂度

## 3.3 技术选型参考（极简）

- 大规模预训练：并行文件系统 Lustre/BeeGFS 或 Ceph 全闪 + RDMA/NVMe-oF
- 训推一体数据湖：Ceph、RustFS、ParaStor，S3+POSIX 双协议
- 大模型推理（长上下文）：GPU HBM+DRAM + 本地 NVMe + 独立分布式 KV 存储池
- RAG 向量检索：向量数据库 + 底层全闪分布式存储
- 前沿原型：AI SSD、近存计算、存内计算
