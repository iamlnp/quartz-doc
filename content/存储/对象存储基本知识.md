# 1 存储桶
存储桶是对象存储的核心组织单元，相当于“云端文件夹”，所有对象（文件、数据）都必须存储在存储桶中，是管理对象的基础载体。

## 1.1 存储桶的核心定位
存储桶是对象存储的顶层命名空间，用于隔离和管理不同用途的对象数据，每个存储桶有唯一的全局名称（跨云厂商/区域唯一），同时关联特定区域（如华东、北美），对象存储在对应区域的存储集群中。
## 1.2 核心特性与配置
- 基础属性：有固定区域（创建后不可修改）、存储类型（默认标准存储，可搭配生命周期转换）、访问权限（公开/私有/自定义ACL）。
- 关键配置：支持启用版本控制（保留对象历史版本，防止误删）、跨域资源共享（CORS，允许前端跨域访问）、服务器端加密（SSE）、日志记录（记录访问行为）。
- 命名规则：名称由字母、数字、短横线组成，不能包含特殊字符，长度通常在3-63字符，需全局唯一（如OSS的bucket名称全网唯一）。

## 1.2.1 与其他功能的关联
- 对象管理：所有对象（文件）必须隶属于某个存储桶，通过“存储桶名称+对象键（路径/文件名）”唯一标识。
- 权限控制：存储桶的ACL或IAM策略，会直接作用于桶内所有对象，也可针对对象单独配置权限（优先级高于桶权限）。
- 上层功能依赖：存储桶事件、复制、生命周期等功能，均需以存储桶为单位配置，规则仅作用于该桶内的对象。

# 2 访问密钥
对象存储的访问密钥是用于身份验证的安全凭证，核心作用是授权用户/应用访问对象存储资源。

## 2.1 核心定义
访问密钥是对象存储服务（如S3、OSS等）发放的成对安全凭证，通常包含“访问密钥ID”和“秘密访问密钥”两部分，相当于访问存储资源的“账号+密码”。
## 2.2 关键特点
- 访问密钥ID：公开标识，用于告知服务端访问者身份，不具备直接访问权限。
- 秘密访问密钥：私密凭证，需严格保管，用于服务端验证身份合法性，泄露会导致资源风险。
- 作用范围：控制桶、对象的读写、删除等操作，权限可通过IAM策略灵活配置。

## 2.3 使用场景
- 应用程序集成对象存储时，通过密钥发起API请求。
- 第三方工具（如备份软件、FTP客户端）连接存储服务时的身份验证。
- 命令行工具（如AWS CLI、ossutil）操作存储资源的授权依据。

# 3 IAM 策略
## 3.1 核心定义
IAM（身份与访问管理）策略是基于JSON格式的权限规则文档，通过绑定用户、角色或访问密钥，明确授权范围和操作限制，是对象存储权限管控的核心手段。

## 3.2 关键组成要素
- 主体（Principal）：被授权的对象，如用户、角色、访问密钥对应的账号。
- 资源（Resource）：被访问的对象存储资源，如存储桶（Bucket）、对象（Object）。
- 操作（Action）：允许执行的具体操作，如上传（PutObject）、下载（GetObject）、删除（DeleteObject）。
- 条件（Condition）：权限生效的约束条件，如指定IP地址、访问时间、请求来源。
- 效果（Effect）：策略执行结果，分为“允许（Allow）”或“拒绝（Deny）”，拒绝优先级高于允许。

## 3.3 常见策略类型
- 基于身份的策略：直接绑定到用户/角色，控制该主体的所有访问行为。
- 基于资源的策略：绑定到存储桶/对象，控制所有访问该资源的主体权限。
- 托管策略：云厂商预设的通用策略（如“只读权限”“管理员权限”），可直接复用。
- 自定义策略：根据业务需求灵活配置的个性化权限规则，精准控制权限范围。

# 4 存储桶事件
存储桶事件是对象存储的“触发器”，当存储桶内发生特定操作时，自动触发预设的后续动作。
- 核心触发场景：对象上传、删除、修改、恢复，存储桶权限变更等。
- 常见目标动作：发送通知到消息队列（如MQ、SQS）、调用函数服务（如Lambda、云函数）、推送日志到监控系统。
- 典型用途：上传文件后自动触发转码、删除对象后同步清理缓存、新增文件时发送通知提醒。

# 5 存储桶复制
存储桶复制是跨区域/同区域的数据同步功能，实现存储桶间的对象复制与同步。
- 核心类型：同区域复制（用于数据备份、负载分担）、跨区域复制（用于灾备、就近访问加速）。
- 关键特性：支持同步新上传对象、历史对象批量复制，可选择是否同步对象元数据、访问控制列表（ACL）。
- 典型用途：异地灾备（防止区域故障导致数据丢失）、多区域部署（让不同地区用户就近获取数据）。

# 6 生命周期
生命周期是对存储桶内对象的“自动化生命周期管理”，按预设规则自动执行存储类型转换或删除操作。
- 核心规则：对象达到指定时间后，从标准存储转换为低频访问/归档存储（降低成本）；过期对象自动删除（清理无效数据）。
- 关键配置：基于对象创建时间、最后访问时间设定规则，支持按前缀、标签筛选目标对象。
- 典型用途：冷数据归档（如半年前的日志转归档存储）、自动清理临时文件（如7天后自动删除备份缓存）。

# 7 服务器端加密 (SSE)和KMS
对象存储数据加密的核心组合，SSE是加密实现方式，KMS密钥是加密的“核心钥匙”，搭配使用能保障数据安全。

## 7.1 服务器端加密（SSE）配置
SSE是对象存储在服务器端对数据进行加密的方式，数据上传到存储桶后自动加密，下载时自动解密，对用户透明。
- 核心加密场景：存储桶内所有对象默认加密、指定前缀/标签的对象加密，支持上传时触发加密。
- 常见加密类型：SSE-S3（使用存储服务自带的默认密钥）、SSE-KMS（使用KMS托管密钥）、SSE-C（用户提供自定义密钥），其中SSE-KMS灵活性和安全性最高。
- 配置要点：在存储桶设置中启用“服务器端加密”，选择加密类型，指定对应的密钥（如KMS密钥ID），可设置为强制加密（未加密对象禁止上传）。
## 7.2 KMS密钥
KMS（密钥管理服务）是专门管理加密密钥的服务，KMS密钥是SSE加密的核心，用于加密/解密对象数据的“主密钥”。
- 核心类型：默认服务密钥（云厂商预设，无需手动创建）、用户自定义密钥（用户自行创建和管理，权限更可控）。
- 关键特性：密钥支持轮换（定期更换密钥，降低泄露风险）、权限管控（通过IAM策略限制谁能使用密钥）、审计日志（记录密钥使用行为，便于追溯）。
- 与SSE的关联：配置SSE-KMS加密时，需指定KMS密钥ID，对象加密时会用该KMS密钥加密生成“数据密钥”，再用数据密钥加密对象，KMS密钥仅用于管理数据密钥。
