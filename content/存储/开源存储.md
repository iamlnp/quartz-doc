区分两类：   
1）**通用开源分布式存储**（可以用来跑 AI 训练 / 数据湖，不是专为 AI 设计，但行业大量用于 AI 集群底座） 
2）**AI 原生开源存储项目**（专门面向大模型训练、KV Cache 推理、向量检索、RAG，感知 GPU/LLM 负载）  

# 1 通用开源分布式存储（AI 训练 / 数据湖底座）  
## 1.1 3FS（Fire-Flyer File System，深度求索 DeepSeek 开源）
- 定位：**专为大模型预训练设计的并行文件系统**，近年最火 AI 训练存储，完全开源
- 底层：元数据基于 FoundationDB；数据层 NVMe SSD + RDMA，CRAQ 链式复制协议
- 能力：极高聚合读带宽，支持 Checkpoint、训练 shuffle；也可以承载 KV Cache 卸载
- 协议：POSIX，S3 兼容；适合万卡级 LLM 预训练、微调
- github：deepseek-ai/3FS
- 特点：无中心化 MDS 单点瓶颈，实测大规模集群 6.6TiB/s 读吞吐

## 1.2 DAOS（Intel）

- 定位：HPC/AI 高性能对象 + KV 存储，开源 BSD 协议
- 介质原生：面向 NVMe SSD+PMem，低延迟、高 IO500 跑分；适合小文件 + 混合负载
- 场景：AI 训练、HPC，元数据性能强；支持 GDS/GPU Direct Storage
- 不足：生态相对窄，运维门槛高

## 1.3 Lustre

- 经典并行 POSIX 文件系统，GPLv2；超算 / 传统大模型训练标配
- 优势：超大聚合带宽，成熟；缺点：元数据 MDS 单点，海量小文件差，运维重
- 场景：大规模预训练集群

## 1.4 Ceph（RADOS）

- 统一存储：对象 S3 + CephFS 文件 + 块存储；LGPL 开源
- 训推一体数据湖首选，一套集群承载原始数据集、模型权重、checkpoint、RAG 文档
- 优点：弹性扩容、EC 纠删码、多协议；缺点：纯顺序带宽不如 Lustre/3FS，全闪集群调优成本高

## 1.5 BeeGFS（FhGFS）

- 并行 POSIX 文件系统，社区版开源；中等规模 AI 训练集群，易用性优于 Lustre
- 特点：部署简单，元数据分布式；大规模万卡场景不如 Lustre/3FS

## 1.6 HDFS

- Hadoop 分布式文件系统；适合海量离线 AI 数据集（Parquet、WebDataset），**不适合在线训练高带宽场景**，随机 IO 弱

# 2 LLM 推理专用开源 KV Cache 存储（当前 AI 存储最热门赛道）  

## 2.1.1 Mooncake（月之暗面 Kimi 开源）

- 定位：**存算分离分布式 KV Cache 池系统**（Mooncake Store + Transfer Engine）
- 核心：聚合集群内 DRAM/NVMe，构建全局共享 KV 池；支持 Prefill/Decode 分离架构；RDMA/GPUDirect 零拷贝传输
- 集成：vLLM、SGLang，和 LMCache 深度配套
- github：kvcache-ai/Mooncake
- 场景：长上下文 LLM 推理、KV 跨节点复用，降低 TTFT，提升并发；Kimi 生产环境原生系统

## 2.1.2 LMCache

- 定位：**KV Cache 管理层（不是底层存储，是中间件调度层）**，PyTorch 生态项目
- 能力：KV 跨请求 / 跨引擎复用、分层卸载（显存→DRAM→SSD→远端 Mooncake/infiniStore 后端）、KV 压缩、CacheBlend 前缀检索
- 对接后端：Mooncake、infiniStore、Redis、本地 NVMe；对接推理引擎 vLLM/SGLang
- github：lmcache/lmcacheLMCache

## 2.1.3 InfiniStore

- 开源分布式 KV 存储，专为 LLM 推理 KV Cache 设计；可以独立作为远端 KV 池
- 适配 vLLM+LMCache，支持预填充 / 解码分离集群，跨节点 KV 迁移、共享
- github：infinistore/infiniStore

## 2.1.4 OpenLake

- 开源 KV Cache 卸载引擎；GPU KV 下沉到共享 RAM/NVMe；内置 GPU 端 KV 无损压缩
- 目标：长上下文场景，减少 prefill 重复计算，降低 TTFT
- github：openlakeai/openlakeHacker New...

> 补充：FlexKV，轻量开源 KV 缓存管理，vLLM 生态，小规模 KV 卸载原型项目

# 3 向量存储（RAG 开源向量数据库，AI 检索存储）  
## 3.1.1 Milvus

- 开源云原生向量数据库（Apache2.0），最主流；支持 HNSW/IVF，百亿级向量，冷热分层存储
- 底层可跑在 MinIO/Ceph；混合检索（向量 + 标量过滤）；RAG、多模态检索
- github：milvus-io/milvus

## 3.1.2 Qdrant

- Rust 开发，Apache2.0；向量 + payload 元数据强过滤；单机 / 集群都好部署，中小规模 RAG 首选
- github：qdrant/qdrant

## 3.1.3 LanceDB

- 嵌入式向量存储，Apache2.0；基于 Lance 文件格式，面向磁盘优先，支持 SQL + 向量检索，多模态
- 适合本地 / 边缘 AI、离线向量构建，可直接读对象存储
- github：lancedb/lancedb

## 3.1.4 Weaviate

- Go 开发，向量 + 图原生；向量 + BM25 混合检索，内置实体关系；企业级 RAG
- github：weaviate/weaviate

## 3.1.5 Chroma

- 轻量嵌入式向量库，开箱即用，原型 PoC 首选，不适合超大生产集群
- github：chroma-core/chroma

> 补充：PGVector（Postgres 向量插件），属于数据库扩展，不是独立存储系统   

# AI 数据处理 / 数据集存储辅助开源项目（配套）  
- WebDataset：把海量小样本打包成 tar，解决 AI 训练小文件灾难；配合对象存储使用
- Parquet/Arrow（DuckDB）：AI 数据湖列式存储，用于数据集清洗、特征存储
- LakeFS：S3 兼容的数据版本管理，AI 数据集 / 模型版本控制（类似 git for 数据湖）

# 横向选型简表

|项目|类型|核心场景|优点|短板|
|---|---|---|---|---|
|3FS|并行文件系统|LLM 大规模预训练|超高聚合带宽、RDMA 原生|仅适合 NVMe 全闪，运维较重|
|Ceph|统一分布式存储|训推一体数据湖|S3+POSIX，多协议、弹性|顺序带宽弱于 3FS/Lustre|
|MinIO|对象存储|中小集群数据集、模型权重|极简部署、S3 兼容|不适合万卡高带宽训练|
|Mooncake|分布式 KV 池|LLM 长上下文推理 KV 共享|RDMA 零拷贝，PD 分离架构|主要面向推理，不做训练数据集|
|LMCache|KV 中间件|KV 缓存调度 / 复用|插件化，可插拔后端|依赖底层 KV 存储（Mooncake 等）|
|Milvus|向量数据库|RAG 向量检索|大规模分布式成熟|资源开销较大|
**一句话选型指引**

1. **大模型预训练**：优先 3FS；传统超算 Lustre；中小训练集群 Ceph/MinIO
2. **LLM 推理，长上下文 KV 池化**：Mooncake + LMCache 组合是当前开源社区事实标准
3. **RAG 向量检索**：Milvus（大规模） / Qdrant（中小型） / LanceDB（嵌入式）
4. **训推一体数据湖**：Ceph / MinIO + LakeFS 版本管理
