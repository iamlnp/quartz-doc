# 1 目标文件格式

linux按照ELF（Executable Linkable Format）格式存储：

| 文件类型                       | 说明                                                                                                           | 实例                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| 可重定位文件（Relocatable File）   | 包含代码和数据，可以用来链接成可执行文件或者共享目标文件，静态链接库可以归档为此类                                                                    | Linux的.o<br />Windows的.obj    |
| 可执行文件(Executable File)     | 包含了可以直接执行的程序，代表就是ELF可执行文件，一般没有扩展名                                                                            | /bin/bash文件<br />Windows的.exe |
| 共享目标文件(Shared Object File) | 包含代码和数据，可以在以下两种情况使用：<br />（1）连接器使用，将其与其他可重定向文件和共享目标文件链接，产生新的<br />（2）动态连接器可以讲几个这种共享目标文件与可执行文件结果，作为进程影响的一部分运行 | Linux的.so<br />Windows的DLL    |
| 核心转储文件(Core Dump File)     | 进程意外终止时，系统可以将该进程的地址空间内存及终止时的一些其他信息转储到核心转储文件                                                                  | Linux的core                    |

命令行**file**可以查看文件类型

```shell
$ file msstore.o
msstore.o: ELF 64-bit LSB relocatable, x86-64, version 1 (SYSV), not stripped
```

# 2 目标文件内容

一般目标文件将信息按照不同的属性，以“节”(Section)的形式存储，有时候也叫做“段”(Segment)。

源码编译后的机器指令经常放在**代码段**里，代码段常见的名字是".code"或者".text"; 全局变量和局部静态变量数据经常放在**数据段**里，一般名字叫做".data"。

一般C语言的编译后，

- 执行语句都编译成机器代码，保存在.test段
- 已经初始化的全局变量和局部静态变量保存在.data段
- 未初始化的全局变量和局部静态变量保存在.bss段（预留位置，不占空间）

# 3 深入剖析目标文件

后续的剖析均以下列文件(simple_section.cc)为例：

```c
// 通过gcc -c simple_section.cc
int printf(const char *format,...);

int global_int_var = 84;
int global_uninit_var;

void func1(int i) 
{
  printf("%d\n", i);
}

int main(void) {
  static int static_var1 = 85;
  static int static_var2;
  
  int a = 1;
  int b;
  
  func1(static_var1 + static_var2 + a + b);
  
  return a;
}
```

**段描述符**：
```c
typedef struct
{
  Elf64_Word	sh_name;		/* Section name (string tbl index),段名 */
  Elf64_Word	sh_type;		/* Section type，段类型 */
  Elf64_Xword	sh_flags;		/* Section flags，段标志位 */
  Elf64_Addr	sh_addr;		/* Section virtual addr at execution，段虚拟地址 */
  Elf64_Off	    sh_offset;		/* Section file offset，段偏移，表示段在文件中的偏移 */
  Elf64_Xword	sh_size;		/* Section size in bytes，段长度 */
  Elf64_Word	sh_link;		/* Link to another section */
  Elf64_Word	sh_info;		/* Additional section information */
  Elf64_Xword	sh_addralign;		/* Section alignment，段地址对齐 */
  Elf64_Xword	sh_entsize;		/* Entry size if section holds table，Section Entry项的长度 */
} Elf64_Shdr;
```
**段的类型**: 段的名字只有在链接和编译过程中有意义，决定段的属性的是段类型(Type)和段标记位(Flags)。

| 类型名称 | 含义                 |
| -------- | -------------------- |
| NULL     | 无效段               |
| PROGBITS | 程序段               |
| SYMTAB   | 表示该段内容是符号表 |
| STRTAB   | 该段内容是字符串表   |
| RELA     | 重定位表             |
| HASH     | 符号表的哈希表       |
| DYNAMIC  | 动态链接信息         |
| NOTE     | 提示性信息           |
| NOBITS   | 该段在文件中没有内容 |
| REL      | 该段包含了重定位信息 |
| SHLIB    | 保留                 |
| DNYSYM   | 动态链接的符号表     |

**段标志位**表示该段在进程虚拟地址空间的属性。

| 名称      | 值   | 含义                       |
| --------- | ---- | -------------------------- |
| WRITE     | 1    | 该段在进程空间可写         |
| ALLOC     | 2    | 该段在进程中间需要分配空间 |
| EXECINSTR | 4    | 该段在进程空间中可以被执行 |

**段的链接信息**（Link、Info)：如果段类型与链接相关，比如从定位表和符号表，那么这两个成员才有意义。

## 4.3 重定位表

连接器在处理目标文件时，需要对目标文件中某些部位进行重定向，即代码段和数据段中那些对绝对地址的引用位置。对于每个需要重定位的代码段或者数据段，都会有相应的重定位表。比如前面例子中".rela.text"就是对".text"的重定位表，因为”.text“中至少有一个对绝对地址的引用，那就是对”printf“函数的调用。

## 4.4 字符串表

在ELF文件中引用字符串只需要给出一个数字下标即可，不用考虑字符串长度问题。一般字符串表也以段的形式保存，常用的段名是".strtab"或者".shstrtab"，分别表示**字符串表**和"**段表字符串表**"。



# 5 符号 - 链接的接口

在链接中，函数和变量统称为**符号**, 函数名或者变量名就是**符号名**， 每个目标文件都有一个相应的**符号表**， 每个定义的符号有一个对应的值，叫做**符号值**。

```shell
[root@liunp ~]# readelf -s simple_section.o

   Num:    Value          Size Type    Bind   Vis      Ndx Name
     0: 0000000000000000     0 NOTYPE  LOCAL  DEFAULT  UND
     1: 0000000000000000     0 FILE    LOCAL  DEFAULT  ABS simple_section.c
     2: 0000000000000000     0 SECTION LOCAL  DEFAULT    1
     3: 0000000000000000     0 SECTION LOCAL  DEFAULT    3
     4: 0000000000000000     0 SECTION LOCAL  DEFAULT    4
     5: 0000000000000000     0 SECTION LOCAL  DEFAULT    5
     6: 0000000000000004     4 OBJECT  LOCAL  DEFAULT    3 static_var1.1965
     7: 0000000000000000     4 OBJECT  LOCAL  DEFAULT    4 static_var2.1966
     8: 0000000000000000     0 SECTION LOCAL  DEFAULT    7
     9: 0000000000000000     0 SECTION LOCAL  DEFAULT    8
    10: 0000000000000000     0 SECTION LOCAL  DEFAULT    6
    11: 0000000000000000     4 OBJECT  GLOBAL DEFAULT    3 global_int_var
    12: 0000000000000004     4 OBJECT  GLOBAL DEFAULT  COM global_uninit_var
    13: 0000000000000000    34 FUNC    GLOBAL DEFAULT    1 func1
    14: 0000000000000000     0 NOTYPE  GLOBAL DEFAULT  UND printf
    15: 0000000000000022    51 FUNC    GLOBAL DEFAULT    1 main
```

列名解释：

- Num:在符号表中偏移下标
- Value:符号对应的值，可能是绝对值，也可能是地址
- Size: 符号大小
- Type：类型信息
  - NOTYPE： 位置符号类型
  - OBJECT：数据对象，比如 变量、数组
  - FUNC：函数或者可执行代码
  - SECTION：表示一个段
  - FILE：表示文件名，一般都是该目标文件所对应的源文件名
- Bind: 绑定信息
  - LOCAL：局部符号，对于目标文件的外部不可见
  - GLOBAL：全局符号，外部可见
  - WEAK：弱引用
- Vis：C/C++未使用
- Ndx：符号所在段，如果符号定义在本目标文件，则表示所在的段在段表中小标，否则是特殊符号
  -  ABS：包含绝对值，比如文件名
  - COMMON：该符号是一个“COMMON块”类型的符号，比如未初始化的全局符号定义
  - UNDEF：未定义，表示该符号在本目标文件被引用，但是定义在其他目标文件中

## 5.1 弱符号和强符号

```shell
b.o: (.data+0x0):mutiple definition of 'global'
a.o:（.date+0x0):first defined here
```

编译器默认函数和初始化了的全局变量为**强符号**，未初始化的全局变量为**弱符号**，强符号链接时重复定义会报上述错误，通过`__attribute__((weak))可以定义一个强符号为弱符号。

对外部目标文件的符号引用被最终链接为可执行文件时，如果找不到该符号的定义，链接器报未定义错误，这类为**强引用**，与之相对的弱引用，如果该符号未定义，链接器不报错，通过'__attribute__((weakdef))'可以声明一个外部函数的引用为**弱引用**。
