# 装载方式

- 覆盖载入(Overlay)
- 页映射(Paging)

原则上都是利用了程序的局部性原理，动态载入的四项就是程序用到哪个模块，就将那个模块装入内存，如果不用就暂时不装入，存放在磁盘里。

# 进程虚拟空间分布

## ELF文件链接视图和执行视图

在ELF文件中，段的权限往往只是几种为数不多的几种组合：

- 以代码段为代表的权限为可读可执行的段
- 以数据段和BSS段位代表的权限为可读可写的段
- 以只读数据为代表的权限为只读的段

**将相同权限的段，把它们合并到一起当做一个段进行映射**。

ELF可执行文件引入一个概念叫做”Segment", 一个“Segment”包含一个或者多个类似的“Section", "Segment"的概念实际上是从装载的角度重新划分了ELF的各个段。
ELF 可执行文件中有一个专门的数据结构叫做程序头表 (Program Header Table)用 来保存“Segment” 的信息。ELF 目标文件不需要被装载，所以它没有程序头表，而ELF的可执行文件和共享库文件都有。

## 堆和栈

操作系统通过给进程空间划分一个个的VMA来管理进程的虚拟空间；基本原则是将相同权限属性的、有相同映像文件的映射成一个VMA；一个进程基本上可以划分为如下几种VMA区域：

`cat /proc/pid/maps`可以查看进程的虚拟空间分布

- 代码VMA，只读可执行；有映像文件
- 数据VMA，可读写可执行；有映像文件
- 堆VMA，可读写可执行，无映像文件，匿名，可向上扩展
- 栈VMA，可读写不可执行，无映像文件，匿名，可向下扩展



## 动态链接实例

```c 
//program1.c
#include "Lib.h"

int main() {
  foobar(1);
  return 0;
}

//program2.c
#include "Lib.h"

int main() {
  foobar(2);
  return 0;
}

//Lib.c
#include <stdio.h>
void foobar(int i)
{
	printf("Printing from Lib.so %d\n", i);
}

//Lib.h
#ifndef LIB_H
#define LIB_H

void foobar(int i);

#endif
```

使用`gcc -fPIC -shared -o Lib.so Lib.c`编译生成动态库，然后编译链接Program1.c和Program2.c

`gcc -o Program1 Program1.c ./Lib.so`和`gcc -o Program2 Program2.c ./Lib.so`
