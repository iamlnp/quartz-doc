# 1 通用概念
MCP：Model Context Protocol，模型上下文协议
背景：大模型本身只会问答，不会使用工具，MCP则相当于让大模型具有了使用外部工具能力

## 1.1 MCP host
本质上是支持MCP协议的软件， 常见的有Claude Desktop，Cursor，Cline，Cherry Studio
### 1.1.1 Cline
Cline 编程助手的 **Plan 与 Act 模式**，二者是 “先规划、后执行” 的双模式开发流程，核心区别在于权限、职能与适用场景，用于控制 AI 编程的 “思考 - 动手” 边界，提升可控性与效率
核心区别总览

| 维度    | Plan 模式（规划）                   | Act 模式（执行）                               |
|-------|-------------------------------|------------------------------------------|
| 核心职能  | 需求分析、架构设计、方案制定、风险评估           | 代码生成、文件修改、终端执行、按计划落地                     |
| 代码权限  | 只读，禁止修改 / 创建 / 删除文件           | 读写，可直接编辑代码、新建文件、运行命令                     |
| 上下文能力 | 全文件读取，全局理解项目                  | 继承 Plan 阶段上下文，聚焦具体实现                     |
| 交互风格  | 多轮对话澄清需求，输出步骤化方案              | 按既定方案静默执行，关键操作需用户确认                      |
| 适用场景  | 新功能设计、复杂调试、架构决策、需求拆解          | 既定方案编码、常规 Bug 修复、测试用例编写、命令执行             |
| 模型适配  | 优先推理强模型（如 DeepSeek R1、GPT-4o） | 优先编码强模型（如 Claude 3.5 Sonnet、DeepSeek-V3） |
| 典型输出  | 技术方案、实施路线图、架构图、任务清单           | 可运行代码、文件变更、终端命令结果                        |

## 1.2 AI 模型
AI 模型（AI Model）是**通过数据训练得到的数学 / 算法框架**，能根据输入数据（文本、图像、语音等）输出符合预期的结果（预测、生成、分类等），本质是 “用数据喂出来的智能规则集合”。  
- 通俗类比：把 AI 模型看作 “经过海量习题训练的学霸”，输入一道题（任务），它能根据训练经验给出答案（输出）；
- 核心价值：替代 / 辅助人类完成复杂认知任务（如语言理解、代码生成、图像创作）。

### 1.2.1 AI 模型的核心分类（按任务 / 架构）
1. 按核心任务分类（最易理解）：

| 类别         | 核心能力                   | 典型模型 / 应用                                  |
|------------|------------------------|--------------------------------------------|
| 大语言模型（LLM） | 理解 / 生成文本、代码，支持对话 / 推理 | GPT-4o、Claude 4.5、DeepSeek-V3-0324、Llama 3 |
| 多模态模型      | 处理文本 + 图像 + 语音等多类型数据   | GPT-4V、Gemini 2.0、Qwen-VL                  |
| 图像生成模型     | 根据文本 / 图像生成新图像         | Stable Diffusion、Midjourney、DALL·E 3       |
| 语音模型       | 语音识别 / 合成、语音转文字        | Whisper、讯飞星火语音模型                           |
| 推荐 / 预测模型  | 行为预测、内容推荐              | 抖音推荐模型、电商个性化推荐模型                           |
2. 按架构分类（技术维度）：

| 架构               | 核心特点            | 代表模型                            |
|------------------|-----------------|---------------------------------|
| Transformer（主流）  | 自注意力机制，并行计算效率高  | 几乎所有主流 LLM（GPT/DeepSeek/Claude） |
| MoE（混合专家）        | 稀疏激活，大参数 + 高效率  | DeepSeek-V3、GPT-4 Turbo、PaLM 2  |
| CNN（卷积神经网络）      | 擅长图像特征提取        | ResNet、图像分类模型                   |
| RNN/LSTM（循环神经网络） | 擅长时序数据（语音 / 文本） | 早期语音识别模型                        |
### 1.2.2 主流 AI 模型的关键参数（看懂模型能力的核心）：  
不管是 DeepSeek-V3-0324 还是 GPT-4o，核心参数决定了模型的能力边界：
1. **参数量**：模型中可训练的参数总数（如 DeepSeek-V3 总参 671B），通常参数量越大，能力越强，但推理成本越高；
    - 补充：MoE 模型有 “总参数” 和 “激活参数” 之分（如 DeepSeek-V3 激活参数 37B），激活参数才是单次推理实际用到的参数，平衡了能力与效率。
2. **上下文窗口**：模型能处理的最大输入文本长度（如 DeepSeek-V3 支持 128K），窗口越大，能处理的长文本 / 对话历史越多。
3. **推理性能指标**：
    - 通用能力：MMLU（多学科推理）、GPQA（复杂推理）；
    - 代码能力：HumanEval、LiveCodeBench；
    - 中文能力：C-Eval、AGIEval。
4. **部署 / 调用方式**：
    - API 调用：通过服务商（OpenAI/DeepSeek/OpenRouter）提供的接口调用，无需自己部署；
    - 私有化部署：下载模型权重，部署在本地 / 企业服务器，数据更安全，但需算力支持。

### 1.2.3 AI 模型的使用流程（通用实操框架）
以调用 DeepSeek-V3-0324 这类 LLM 为例，核心步骤通用：
1. **获取密钥**：在模型服务商官网（DeepSeek/OpenRouter）注册，生成 API Key；
2. **选择接入方式**：
    - 轻量使用：直接用服务商提供的网页版（如 DeepSeek 对话界面）；
    - 开发集成：通过 API 调用（兼容 OpenAI 格式，改 base_url 和 Key 即可）；
3. **参数调优**：根据需求调整 temperature（随机性，0~1）、top_p（采样范围）、max_tokens（输出长度）；
4. **结果验证**：核对模型输出的准确性，复杂任务（如代码生成）需测试 / 校验。

## 1.3 API Provider（API 服务商 / 提供商）
**API Provider** 就是**提供 API 接口的平台 / 公司 / 服务方**，是背后提供 AI 能力、数据能力或功能服务的主体，你通过调用它的 API，才能使用其对应的服务（比如 AI 模型、数据查询、工具功能等）。  
结合之前提到的**OpenRouter**和**Cline AI**场景，分两层理解更清晰：
1. **原生 API 服务商**：直接开发并提供 API 的官方平台，比如 OpenAI（GPT 系列）、Anthropic（Claude 系列）、Google（Gemini 系列）、阿里云 / 腾讯云的 AI 平台，这些是**底层 API Provider**；
2. **聚合 API 服务商**：像 OpenRouter 这类平台，本身聚合了几十家原生服务商的 API，对外提供统一接口，此时**OpenRouter 也属于 API Provider**（二次聚合型）。

**核心特征**：API Provider 会定义 API 的调用规则、格式、计费方式，同时发放用于身份验证的 API Key，保障接口的合法调用和用量统计。

## 1.4 API Key（应用程序接口密钥）
**API Key** 是 API Provider 为你分配的**唯一身份验证字符串**，相当于你调用某个 API 的「身份证 + 门禁卡」，核心作用是**验证调用者的合法性、统计接口使用量、进行权限 / 计费管控**

**关键特点 & 使用规则**： 
1. **唯一性**：每个账号 / 应用的 API Key 都是独有的，与你的账号绑定；
2. **保密性**：属于敏感信息，**绝对不能公开**（比如写在开源代码、公开发布的脚本里），否则可能被他人盗用，产生高额费用；
3. **必备性**：调用几乎所有商用 API 时，都需要在请求中携带 API Key（通常放在请求头、参数里），服务商通过它识别调用者；
4. **可管控**：API Provider 的后台通常支持创建 / 删除 / 重置 API Key，还能为不同 Key 设置权限（如仅调用某类模型）、用量限制（如每日调用次数），即使泄露也能快速作废。

举例：  
以**Cline AI 对接 OpenRouter 调用 Claude 模型**为例，三者的关系一目了然：
```txt
Cline AI（本地编程助手） → 调用 → OpenRouter（聚合API Provider） → 调用 → Anthropic（原生API Provider）
```
- 你需要先在**Anthropic**（原生）获取 API Key，也可以直接在**OpenRouter**（聚合）获取专属 API Key（更便捷，因为 OpenRouter 已对接原生服务商）；
- 将**OpenRouter 的 API Key**配置到 Cline AI 中，Cline AI 就能通过这个 Key，合法地向 OpenRouter 发起 API 请求，进而使用 Anthropic 的 Claude 模型；
- OpenRouter 会通过这个 API Key，统计你的调用量、扣取费用，同时验证你是合法用户。 

**通俗类比**：  
把 API 想象成**运营商的网络服务**：  
- **API Provider** = 中国移动 / 中国联通（提供网络服务的主体）；
- **API Key** = 你的手机 SIM 卡（唯一身份标识，没有它无法连网，运营商通过它记费、管控你的套餐）；
- 你用 Cline AI 调用 API = 你用手机连网上网（手机 = Cline AI，上网 = 调用 API 能力）。
