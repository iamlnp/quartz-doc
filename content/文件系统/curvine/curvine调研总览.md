# 核心信息速览  
| 项目维度 | 具体信息                                               |
|------|----------------------------------------------------|
| 项目定位 | 高性能分布式文件缓存系统，作为计算与底层存储（如S3、HDFS）之间的加速层。            |
| 核心目标 | 为计算任务（如AI训练、大数据分析）提供高吞吐、低延迟、低资源消耗的数据访问通道。          |
| 技术栈  | 采用 Rust 语言构建，确保高性能与内存安全。                           |
| 授权协议 | Apache License 2.0 开源协议，允许免费商用和二次开发。               |
| 主要场景 | 训练加速、模型分发、热表数据加速、大数据Shuffle加速、多云数据缓存。              |
| 托管平台 | GitHub 组织 CurvineIO。截至2026年4月，已收获558个Star和66个Fork。 |
| 开发状态 | 活跃开发中，项目代码持续更新。                                    |
| 名称寓意 | 名称由“Curvature”（曲率）与“Engine”（引擎）组合而成，灵感来自科幻小说《三体》。  |
Curvine聚焦于**文件级缓存**，而非KV缓存：  
1. **高性能与低延迟**：通过“零拷贝”（Zero-copy）技术、异步操作等手段优化数据读写管道，实现毫秒级延迟
2. **极致的资源节约**：在相同负载下，相比Java方案可降低进程约90%的内存资源消耗，运维成本更低
3. **原生云支持与POSIX协议**：同时支持 S3 和 HDFS 协议，提供**缓存模式**和**FS模式**。FS模式支持完整POSIX语义，可将对象存储当作本地盘访问，方便传统应用迁移
设计与架构：  
1. **缓存而非存储**：Curvine是加速层，**不负责数据持久化**。它缓存元数据和数据块，所有持久化数据仍需写入底层UFS（如OSS、HDFS）
2. **三层解耦架构**：代码中抽象出的 `UnifiedFileSystem` 接口，可统一处理对Curvine原生缓存和外部UFS的调用，架构清晰，扩展性强
3. **多级缓存策略**：系统内部可能实现了客户端、服务端等多级缓存策略，以进一步优化性能
